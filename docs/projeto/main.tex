\begin{resumo}
O presente trabalho documenta a especificação e o projeto da plataforma ``Preço Bão'', destinada à pesquisa, comparação e acompanhamento de preços de medicamentos e produtos de farmácia. O objetivo é relacionar os requisitos do sistema aos artefatos de modelagem, persistência, interface e planejamento de testes. O procedimento de consolidação consiste na leitura dos documentos existentes e na conferência de modelos, contratos de dados, rotas, serviços e configurações do repositório, distinguindo funcionalidades previstas de componentes presentes no código. A implementação examinada organiza um backend FastAPI e um frontend React Native com Expo em um monorepo, com persistência PostgreSQL e coleta de ofertas em fontes públicas. O documento apresenta minimundo, requisitos funcionais e não funcionais, casos de uso, classes, diagrama entidade-relacionamento, dicionário de dados, protótipo de interface e plano de testes. As Práticas 1 e 2 do oitavo período acrescentam análise de riscos de manutenção, alternativas de intervenção, backlog e plano coletivo de sincronização de favoritos, registrados como propostas. A conferência identifica componentes de autenticação, favoritos, catálogo e histórico, além de limitações em recuperação de senha, geolocalização, retenção de dados e automação de qualidade. Os casos do plano permanecem pendentes, sem atribuição de resultados de execução. Conclui-se que a documentação deve preservar os objetivos aprovados e explicitar as diferenças entre planejamento e implementação, sem tomar a existência do código como comprovação de validação operacional ou de conformidade normativa.
\par\vspace{\onelineskip}
\noindent
\textbf{Palavras-chave:} engenharia de software; especificação de requisitos; \textit{web scraping}; modelagem de sistemas; arquitetura de \textit{software}.
\end{resumo}

% Abstract
\begin{resumo}[Abstract]
\begin{otherlanguage*}{english}
This work documents the specification and design of the ``Preço Bão'' platform, intended for searching, comparing, and tracking prices of medicines and pharmacy products. Its objective is to relate system requirements to modeling, persistence, interface, and test planning artifacts. The consolidation procedure consists of reading existing documents and examining models, data contracts, routes, services, and repository configurations, distinguishing planned features from components present in the code. The implementation examined organizes a FastAPI backend and a React Native frontend with Expo in a monorepo, with PostgreSQL persistence and offer collection from public sources. The document presents the domain description, functional and nonfunctional requirements, use cases, classes, entity-relationship diagram, data dictionary, interface prototype, and test plan. Practices 1 and 2 from the eighth academic term add maintenance risk analysis, intervention alternatives, a backlog, and a collective favorites synchronization plan, recorded as proposals. The examination identifies authentication, favorites, catalog, and history components, as well as limitations in password recovery, geolocation, data retention, and quality automation. Test plan cases remain pending, with no execution results attributed to them. The work concludes that documentation should preserve approved objectives and explain the differences between planning and implementation, without treating the existence of code as evidence of operational validation or regulatory compliance.
\par\vspace{\onelineskip}
\noindent
\textbf{Keywords:} software engineering; requirements specification; web scraping; systems modeling; software architecture.
\end{otherlanguage*}
\end{resumo}
